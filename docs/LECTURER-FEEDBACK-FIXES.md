# Part 2 feedback - what was changed

| Feedback (Part 2) | What we changed | Where to see it |
|---|---|---|
| **SSO:** the API trusts whatever email the client sends; verify the provider token server-side. | The app now sends the **Firebase ID token**. The API verifies its signature against Google's public keys and checks issuer, audience (our Firebase project) and expiry before reading the email from inside the token. Unverified emails are rejected. | `backend/.../Services/FirebaseTokenVerifier.cs`, `AuthController.SsoLogin`; `android/.../auth/GoogleAuthManager.kt` |
| **Settings:** cached session name not refreshed, so reopening settings restores the old name. | After a successful save the API returns the stored values and the app writes the new name into the cached session (`SessionManager.updateFullName`). Settings re-reads the session every time it opens. Unit-tested. | `ProfileRepository.updateSettings`, `SettingsViewModel`, `ProfileRepositoryTest` |
| **UDF1 ISBN scanner:** any EAN-13 is accepted, including non-book products. | The scanner only accepts barcodes with the book prefix **978/979 and a correct check digit**; grocery barcodes show "not a book barcode" and scanning continues. The API validates the ISBN again and looks the book up (Google Books) to pre-fill the title. | `util/IsbnValidator.kt`, `BarcodeScannerScreen.kt`, `Services/IsbnValidator.cs`, `BooksController`; tests on both sides |
| **UDF2 Trade meetings:** buyer/seller ownership not enforced when scheduling or confirming. | Every trade endpoint checks the logged-in user is the buyer or seller (403 otherwise). The code is only shown to the **buyer**; only the **seller** can confirm, by typing the buyer's code at the meeting - so the code now really proves both people met. | `TradesController.cs`; `TradesControllerTests` |
| **UDF3 Karma:** repeated confirmation is not rejected, so points must be awarded once per trade. | Confirmation uses an atomic "confirm only if not yet confirmed" database update; a second attempt returns 409 Conflict and awards nothing. | `TradesController.Confirm`, `Confirm_Twice_AwardsKarmaOnlyOnce` test |
| **GitHub & CI:** workflow stops before building or running tests; add README diagrams and screenshots. | The workflow now builds the app, runs Android and API unit tests, builds debug + signed release APKs and uploads APKs and test reports. README has architecture, data and sequence diagrams and a screenshots section. | `.github/workflows/ci.yml`, `README.md` |
